# ReproCrate v0.7.0 — offline issue drafts (developer pre-release)

**Published experimental pre-release:** https://github.com/sanskarIN/ReproCrate/releases/tag/v0.7.0 on October 18, 2026. **Not stable v1.0.0.** The complete [cross-platform workflow](https://github.com/sanskarIN/ReproCrate/actions/runs/39091493244) passed. GitHub Releases API confirmed six genuine unsigned CLI/desktop executable archives plus six individual SHA-256 files.

The v0.7.0 milestone adds privacy-first local issue drafting across CLI and desktop using the same tested Rust core, preserving the existing report schema and previous CLI workflows.

## New in v0.7.0

- **Offline issue adapters:** GitHub, GitLab, Gitea and generic Markdown formats. No network client, authentication or automatic issue submission.
- **Private by default:** generated drafts omit report title, captured commands/arguments, raw stdout/stderr, paths and finding messages. Only a structural execution status and truncation indicators are included.
- **Explicit review approval:** optionally include shortened masked title, OS/architecture and a capped list of heuristic failure categories; opt-ins require `--acknowledge-reviewed`.
- **CLI:** `reprocrate issue export --report reviewed.json --target github --output issue.md` with no-overwrite output and private Unix permissions.
- **Desktop:** dedicated issue drafting screen with optional disclosures, user consent, complete Markdown preview and explicit save-new action.
- **Shared Rust core:** schema-validated, size-capped Markdown rendering and regression tests for secret omission, unsafe markup and review gates.
- **Verified release gates:** Rust workspace checks and authentic native CLI+desktop binary builds completed on Windows x86-64, Linux x86-64, and macOS ARM64; each archive has a SHA-256 checksum file.

## Important limits

Issue drafts are manual templates and may require editing. Metadata options can still reveal sensitive information; pattern redaction is not proof of complete sanitization. This milestone does not create a GitHub/GitLab/Gitea issue, contact servers, perform automatic reproduction, provide signed installers or certify clean-machine GUI compatibility. All imported content remains inert.
