# ReproCrate v0.9.0 — release quality and security hardening (developer pre-release)

**Published October 18, 2026 as an experimental pre-release:** https://github.com/sanskarIN/ReproCrate/releases/tag/v0.9.0. [Final guarded workflow](https://github.com/sanskarIN/ReproCrate/actions/runs/39099649232) succeeded; GitHub Releases API confirms `draft:false`, `prerelease:true`, and 12 genuine nonempty CLI/desktop archives and checksum sidecars. This milestone prepares for future stable quality; it is not certified v1.0.0.

## Changes

- **Literal Markdown metadata:** report title, command metadata, failure summary and warnings no longer render untrusted inline Markdown links/images as active URLs. HTML delimiters remain encoded. Fenced stdout/stderr are separate and do not execute.
- **Safer CLI report imports:** imports reject non-regular files and symbolic links before attempting to read, including named pipes that may otherwise block indefinitely. Opening checks confirm a regular file, enforce the existing 4 MiB budget and on Unix compare the selected file identity with the opened handle.
- **Core and CLI regressions:** crafted malicious Markdown/HTML metadata tests, symlink/non-regular path tests, and existing privacy behaviors.
- **Real CLI smoke tests:** a portable Python standard-library harness tests the actual *release-built* CLI against temporary inert fixtures; verifies version, offline environment summary, log analysis, checksum matches, checksum tampering and no-overwrite behavior.
- **Stronger release gating:** published-archive SHA-256 is verified by the just-built CLI *before* uploading; a separate strict GitHub Releases manifest validator requires exactly six nonempty CLI/desktop archives and six size-bounded uploaded sidecars with expected platform names and a draft prerelease target.
- **QA evidence:** an explicit cross-platform release-candidate checklist separates CI-evidenced verification from **unperformed** clean-machine GUI, accessibility, signing, license and supply-chain checks.
- Synced Rust workspace, desktop/Tauri, npm package and corresponding lockfiles to v0.9.0, preserving the previous report schema and all offline CLI/desktop capabilities.

## Limitations

No sandboxing of intentionally captured commands, no guarantee that masking detects every secret, no third-party tracker upload, no signed installers/notarization, and no clean-machine GUI QA certification. A successful SHA-256 match is **integrity only**, not authentication or malware scanning. GitHub Pages requires repository-level enablement and must be independently verified before claiming a live site.

The generated RC test matrix is documented in [QA checklist](../qa/release-candidate.md). See [security policy](../../SECURITY.md), [distribution](../reference/distribution.md), and [handoff](../../what_changed.md).

## Verified publication requirements

The final workflow passed complete Rust tests, Clippy, rustfmt and locked dependency inventory validation. Real CLI smoke tests and archive digest checks passed on all three platform builds; Tauri desktop native binaries compiled and uploaded for Linux x86-64, Windows x86-64 and macOS ARM64. The authenticated draft-aware asset manifest check confirmed exactly 12 correctly named uploaded nonempty artifacts, and publication completed successfully. Initial publication retry was needed because GitHub's `releases/tags` REST endpoint returned 404 for the unpublished draft; the final validator uses the authenticated releases listing and unique tag selection. Clean-machine GUI and signed installer verification remain pending.
